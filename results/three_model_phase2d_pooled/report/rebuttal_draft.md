To test whether the forecasting tunnel depends on reading each model where its own head reads, we repeated the layerwise probing with a generic readout: the mean of the valid content-token states at each depth, followed by one linear head to the full horizon, fitted and selected exactly as the native probes on the same windows and targets (all 14 datasets for each of the three models). Compared with the architecture-aware readout, the sustained 5% entrance and the final-block test loss were: Chronos-2: same entrance on 3 of 14 datasets (9 within one block), final-block test loss +27.2% vs the native readout (worse on 12, better on 1, paired CI); TimesFM-3: same entrance on 4 of 14 datasets (8 within one block), final-block test loss +15.9% vs the native readout (worse on 14, better on 0, paired CI); TiRex: same entrance on 3 of 14 datasets (6 within one block), final-block test loss +20.9% vs the native readout (worse on 13, better on 0, paired CI). Holding the head fixed and changing only which token states are read (the native readout tokens versus the mean of all content tokens) changed the final-block test loss by Chronos-2 +11.1% (worse on 12, better on 1); TimesFM-3 +15.9% (worse on 14, better on 0); TiRex +15.6% (worse on 13, better on 0). For Chronos-2 and TiRex the generic readout also has a different head shape and parameter count, so we report it next to the native-mean control rather than as a pure representation comparison.
